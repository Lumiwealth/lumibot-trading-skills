- CRITICAL FOR FUTURES: For Asset.AssetType.FUTURE, ALWAYS use the ROOT symbol (e.g., "CL", "ES", "MES") and specify the contract via expiration=... . Do NOT embed month codes / year into Asset.symbol. If you need two different contract months (calendar spread), use two Asset objects with the same root symbol but different expirations.
- CRITICAL ARCHITECTURE RULE: Never assign arbitrary attributes on the strategy instance (self). Do NOT do things like self.name = "...", self.asset = Asset(...), self.quote_asset = Asset(...), self.symbol = "...", etc. These names can collide with Lumibot internals (e.g., self.name) and crash the app or override framework behavior.
- Required pattern: Use self.vars for any state you need to persist between lifecycle methods or restarts (e.g., self.vars.last_signal = "cash"). For temporary values, use local variables. If you need a friendly label for logs, keep it in a local variable or self.vars (e.g., self.vars.strategy_label); never set self.name.
- When you set the parameters, make sure that there's only one spot where they all are, and they should not override each other. For example, what's recommended is to add a parameters = {} dictionary at the top inside of the strategy class. Do not set the parameters again in other places, such as inside of the "if __name__ == "__main__":" area because they will override each other and cause confusion. So just set the parameters once at the top of the strategy class and do not set them again anywhere else.
- Rare-use only: Do NOT implement `tearsheet_custom_metrics(...)` unless the user explicitly asks for strategy-specific tearsheet summary metrics or a client requirement clearly needs non-generic summary rows. Generic reusable metrics belong in QuantStats/LumiBot core. If you use the hook, return only a small dict of unit-clear scalar values; they appear in both `tearsheet.html` and `tearsheet_metrics.json`.
- IMPORTANT: if you are trading Asset.AssetType.CRYPTO_FUTURE then the only way to exit a posotion is to use self.close_position(position.asset). You cannot use self.submit_order() to exit a position for crypto futures, because that will just open a new position on the other side of the trade. So always use self.close_position() to exit a position for crypto futures. If the strategy is trying to exit a position for crypto futures using self.submit_order() for Asset.AssetType.CRYPTO_FUTURE then you should change it to use self.close_position() instead.
- 🚨 PREFER self.indicators FOR TECHNICAL INDICATORS. LumiBot exposes `self.indicators` on every Strategy. It computes from history available at strategy time and reuses identical observed inputs; new or corrected input may require recomputation. Use `self.indicators.<name>(asset, timestep="day", **kwargs)` for the ~130 pandas-ta-classic built-ins (sma, ema, rsi, atr, bbands, macd, adx, stoch, etc.). Single-column indicators return a float; multi-column return an IndicatorRow with attribute access (e.g., `bb.BBL_20_2_0`, `bb.BBU_20_2_0`). For user-defined indicators use `self.indicators.custom("label", fn, asset, timestep="day", **kwargs)` where `fn(df, **kwargs)` receives the full-history DataFrame and returns a Series or DataFrame.
- If the user asks how to rewrite RSI, SMA, EMA, rolling columns, dataframe indicator helpers, or `compute_indicators()` with LumiBot's built-in indicator system, load `lumibot-indicators` and then `references/computing-indicators.md` with `skills reference get` before answering. Do not substitute `lookup_lumibot_docs`, `get_code`, or another broad skill for that resource load on indicator-computation questions.
- 🚨 DO NOT hand-roll `df["col"] = df["close"].rolling(...).mean()` or `df["col"] = df["close"].rolling(...).apply(...)` inside on_trading_iteration. Every iteration would recompute the full-history rolling window — on a 13-year daily backtest that is ~1M redundant operations per indicator. Use `self.indicators.sma(asset, length=N)` / `self.indicators.custom(...)` instead. Preserve the requested mathematical convention and history initialization; performance depends on the data path and observed inputs.
- When porting a legacy `compute_indicators(self, df)` helper to `self.indicators`, pass the *same function* directly to `self.indicators.custom("label", self.compute_indicators, asset, timestep="day")`. Do not inline the rolling math into on_trading_iteration. The custom function should accept a DataFrame `df` (the full history), compute derived columns (rolling windows, EMAs, etc.), and return either a Series (single-column indicator) or a DataFrame (multi-column indicator, keyed the same index). `self.indicators.custom(...)` returns the latest row at the current bar; access columns via attribute (`row.median_200`) or key (`row["median_200"]`). Returns None if the data source has no bars yet.
- `self.indicators` caches results per (asset, timestep, name, kwargs). Different parameter sets (e.g., length=20 vs length=50) produce distinct memoized entries automatically; you do not need to manage cache invalidation. The memo transparently recomputes when the underlying bar series grows, so routed/live backtests stay correct as more bars are prefetched.
- Return values from `self.indicators`: `None` when the data source has no bars for (asset, timestep); `NaN` (or a row of NaNs) when the indicator hasn't accumulated enough bars yet. Guard with `if value is None: return` followed by `if pd.isna(value): return` for multi-column rows check individual columns.

- Options performance reminder: avoid scanning large strike lists and calling `get_greeks()` per strike to “hunt” a target delta; this can flood the downloader queue. Prefer `OptionsHelper.find_strike_for_delta(...)` (keyword args) for delta-based strike selection.
- CRITICAL FOR OPTIONS FEES: When backtesting options strategies, ALWAYS use `TradingFee(per_contract_fee=0.65)` (not flat_fee). The per_contract_fee is multiplied by order quantity (e.g., 40 contracts x $0.65 = $26.00 per leg). Using flat_fee=0.65 would charge only $0.65 total per order regardless of size, which is wrong and drastically undercounts commissions.
